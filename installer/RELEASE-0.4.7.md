# Aster VPN 0.4.7

- Xray 26.9.9 заменён официальным 26.10.21 (SHA-256 архива проверен по GitHub release).
- Воспроизведён дефект HTTP/2 XHTTP: 30 SOCKS-запросов при зависшем TLS создавали 30 физических соединений вместо ограничения 2. Новое ядро в том же тесте создаёт 2. Источник: https://github.com/XTLS/Xray-core/issues/6797 . Тест: tests/xhttp_stalled_handshake.py.
- Показатель HTTPS больше не суммирует 12-секундный тайм-аут первого сайта с временем ответа резервного. Резервная проверка отмечается в статусе; значение не называется ICMP-пингом.
- Версия в заголовке, настройках и запросах подписки определяется по сборке. Версия установщика берётся из csproj.
- Повторный запуск сигнализирует существующему процессу и разворачивает окно из трея. Сигнал сохраняется и во время первого запуска; второму процессу не нужно создавать ещё одно окно или VPN.

Проверка реальных профилей без изменения текущего VPN: Нидерланды, новое ядро — 16/16 HTTPS, загрузка 16 МБ Google CDN 5,4 Мбит/с, HTTPS под нагрузкой 116–1825 мс (20 измерений), контроль после нагрузки 284/295 мс. Старое ядро на том же профиле — загрузка 10,7 Мбит/с, но проверка под нагрузкой и обе проверки после неё завершились ошибкой. Эти короткие последовательные замеры не доказывают увеличение скорости.

При общем повторном проходе: Германия 0/16 и тайм-ауты; Нидерланды 16/16, загрузка не завершила проверку диапазона CDN; Испания — ошибка DNS. Работающий AWG не отключался. Воспроизведение YouTube 4K и полноценный новый системный TUN не проверены. Исправление конкретной регрессии ядра подтверждено локальным сравнением, а не предположением по скорости CDN.

Тесты .NET: 88 успешных проверок. Числа скорости выше включали возможное ожидание последней HTTPS-пробы; измеритель затем исправлен, поэтому они не считаются точным сравнением пропускной способности.
