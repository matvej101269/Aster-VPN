# Aster VPN 1.0.0

## Правила сайтов

- В маршрутизации добавлены списки «Через VPN» и «Напрямую». Домен охватывает поддомены; более точный поддомен имеет приоритет. Сайты имеют приоритет над правилами приложений и GeoIP, служебные подключения и обход LAN сохраняют более высокий приоритет.
- Домены разделяются строками, запятыми, пробелами или точкой с запятой. Поддерживаются HTTP/HTTPS-ссылки, `*.example.com`, кириллические домены. Ссылка задаёт весь домен, без различения страниц. Одинаковый домен в обоих списках отклоняется до сохранения.
- DNS reverse mapping дополняется распознаванием HTTP/TLS/QUIC на 80/443 с пределом 300 мс. При пустых списках дополнительного sniffing нет. Собственный DNS браузера вместе с ECH может скрыть домен и помешать правилу. Для видео нужно добавить и CDN, например googlevideo.com.
- Настройки сохраняются в прежнем защищённом файле; старые версии настроек совместимы. Применение после переподключения. Правила VPN сохраняют защиту от неподдерживаемого IPv6 и переход QUIC → TCP для XHTTP; прямые правила поддерживают нативный QUIC.

## DNS и параллельная нагрузка

Лог `http2: client connection force closed via ClientConn.Close` показывает сбой общего HTTP/2-транспорта DoH. В исходниках sing-box 1.14.3 тайм-аут DNS вызывает сброс общего транспорта: https://github.com/SagerNet/sing-box/blob/v1.14.3/dns/transport/https.go . Сам лог не доказывает причину первоначального тайм-аута: возможна проблема общего VPN-пути, сети или резолвера.

В новой конфигурации два независимых DoH-транспорта Cloudflare/Google работают параллельно через VPN. Используется первый ответ NOERROR либо NXDOMAIN; ошибка одного транспорта не должна отменять исправный ответ другого. Бюджет одного резолвера — 5 секунд. Системный/незашифрованный DNS как резерв для пользовательских запросов не добавлен. Штатные evaluate/respond/race: https://sing-box.sagernet.org/configuration/dns/rule_action/ .

### Проверки 22.10.2026

- 136 проверок .NET пройдены; настоящие sing-box и Xray принимают конфигурации.
- 9 маршрутов сайтов проверены настоящим sing-box через два локальных маркерных прокси: основной домен, поддомены, более точное исключение, похожие имена и общий маршрут.
- Локальный HTTP/2 DoH-тест: 32/32 запроса успешны при тайм-ауте и сбросе основного транспорта; максимальное время 330 мс. Отрицательный NXDOMAIN сохранён. После восстановления основной ответил за 12 мс. Использованы локальные сертификаты с явным доверием; проверка TLS не отключалась.
- Длительный реальный тест штатного VLESS/XHTTP NL с шестью независимыми HTTP-клиентами: четыре загрузки по 32 МБ завершились за 36,5 / 91,4 / 88,3 / 80,0 с; максимальная пауза чтения 1076 мс. Короткие клиенты: 53 и 18 успешных запросов, без ошибок, но у второго задержки достигали 6099 мс.
- Эксперимент с принудительными четырьмя XMUX-соединениями: загрузки не установились, короткие запросы также завершились ошибками. В поставку эта настройка не вошла. Причину этого отдельного сетевого неуспеха нельзя однозначно отделить от колебаний сети.
- Итоговый тест со штатным XHTTP и новым DNS: четыре загрузки по 32 МБ завершились за 16,2 / 36,8 / 40,0 / 18,0 с; максимальная пауза чтения 817 мс. Два независимых коротких клиента — по 47 успешных запросов, 0 ошибок; p95 1098 / 1164 мс, максимум 1368 / 1353 мс. DNS без кэша под той же нагрузкой — 48 успешных запросов, 0 ошибок, максимум 1368 мс. Весь прогон занял 61 с; проверки после нагрузки также прошли.

Последовательные сетевые замеры не доказывают увеличение скорости именно за счёт исправления DNS. Зафиксированы устранение единственного DoH-транспорта как точки отказа и успешный смешанный прогон. Задержки под нагрузкой сохраняются; оба DNS используют общий VPN-канал. Проверка проводилась через прокси-цепочку без изменения текущего системного TUN. Длительное воспроизведение YouTube 4K и работа нескольких реальных приложений в новом TUN отдельно не проверены.
