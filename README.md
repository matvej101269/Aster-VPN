# Aster VPN для Windows

Windows и Android поддерживают обновления из [GitHub Releases](https://github.com/matvej101269/Aster-VPN/releases).
Порядок публикации и проверки обновлений: [UPDATES.md](UPDATES.md).

Нативный клиент WPF/.NET 8 с общим списком серверов и подпиской для VLESS, AmneziaWG и других протоколов. Сетевые ядра: sing-box 1.14.3, Xray 26.10.21, официальный amneziawg-go v3.1.20260828. Интерфейс и исходники созданы в этом проекте; реализация криптографии используется из официальных ядер.

## Запуск

Откройте `dist/AsterVPN/AsterVPN.exe`. Windows запросит права администратора для TUN. На этом ПК .NET Desktop Runtime 8 уже установлен. Папку `core` необходимо сохранять рядом с приложением.

1. Нажмите «＋ Подписка», вставьте HTTPS-ссылку и обновите список. Кнопка «Вставить» на главной также принимает ссылку из буфера.
2. Выберите конкретную строку сервера слева. VLESS и AmneziaWG из одной подписки находятся в одном списке; название выбранного сервера отображается справа. Выбор сохраняется между запусками. Поиск фильтрует по названию страны и протоколу.
3. В боковом меню «Маршрутизация» выберите режим приложений, добавьте процессы/пути и при необходимости страны прямого доступа (`ru, by, kz`). Сохраните.
4. Нажмите большую круглую кнопку справа или дважды щёлкните сервер. Если подключение уже активно и выбран другой сервер, круглая кнопка переключает на него; если выбран текущий — отключает. Успешная проверка HTTPS через VPN отображается отдельно от запуска туннеля.
5. Крестик скрывает окно в трей; VPN продолжает работать. Повторный запуск через ярлык разворачивает существующее окно без второго экземпляра. Двойной щелчок по значку открывает окно. «Выход» в меню трея отключает VPN и завершает клиент.

Настройки меняются при следующем подключении. Обновление подписки не разрывает активный туннель. Оно заменяет общий список серверов актуальным списком провайдера, поэтому добавленные вручную в тот же список профили будут удалены при следующем обновлении.

Интерфейс 0.2: тёмное оформление с лаймовым акцентом, боковая навигация, карточка подписки и отдельная панель соединения. Иконка ↻ обновляет подписку, ◴ проверяет задержки всего списка: TCP для TCP-протоколов, ICMP для AWG и других UDP-протоколов. До проверки показывается «—». ICMP измеряет доступность узла, а не работоспособность VPN; сервер может запрещать ICMP. При активном VPN измерение следует текущим маршрутам Windows. Для проверки самого туннеля используйте HTTPS после подключения. Названия `.conf` из комментария `# Name` сохраняются при импорте.

## Протоколы и форматы

| Протокол | Импорт |
|---|---|
| AmneziaWG 1/2/3/3.1 | `.conf`, `awg://`, `amneziawg://`, `vpn://` с Base64 `.conf`, JSON-контейнер AmneziaWG |
| WireGuard | `.conf`, `wg://`, `wireguard://`, sing-box JSON endpoint |
| VLESS, Reality | URI; TCP, WS, gRPC, HTTP, HTTPUpgrade; XHTTP через Xray |
| VMess | Base64 JSON URI; TCP, WS, gRPC, HTTP |
| Trojan, Shadowsocks | URI, sing-box JSON |
| Hysteria2, TUIC, AnyTLS | URI, sing-box JSON |
| SOCKS4/5, HTTP/HTTPS proxy | URI, sing-box JSON |
| Hysteria v1, SSH, Naive, Snell, ShadowTLS | sing-box JSON; ограничения сборки ядра сохраняются |
| OpenVPN/OpenConnect | sing-box JSON endpoint с встроенными ключами; интерактивная авторизация не реализована |

Подписка: текстовый список URI, обычный/URL-safe Base64 список, sing-box JSON. Можно смешивать `vless://…` и `vpn://<base64-conf>…` в одной подписке. AmneziaWG не преобразуется в обычный WireGuard: параметры обфускации передаются официальному AWG-ядру. `.conf` поддерживает один Peer, секции Interface и Device, базовые параметры и расширения J/S/H/I, HeaderProtectionKey, ContentPaddingAddition, тайминги, RandomTrailers, DisableCookies. Полные пути к приложениям сопоставляются точно; дочерний .exe добавляется отдельно.

Это не поддержка буквально всех VPN-протоколов. Не реализованы Clash YAML, произвольные полные Xray-конфиги, SSR, IKEv2/L2TP, импорт `.ovpn`, цепочки detour, плагины Shadowsocks и запакованные аккаунты Amnezia Premium `vpn://` с JSON/API-токеном. Для таких форматов приложение выдаёт ошибку, не подменяя их другим протоколом. Ваш формат `vpn://` с `.conf` поддерживается. Если одна строка подписки некорректна, обновление отклоняется целиком и старый список остаётся сохранённым.

## Маршрутизация и DNS

- Все приложения через VPN.
- Только приложения из списка через VPN; остальные напрямую.
- Только приложения из списка в обход VPN; остальные через VPN.

При включённом обходе LAN частные сети 10/8, 172.16/12, 192.168/16, fc00::/7 и fe80::/10 исключаются из маршрутов TUN: Windows обращается к ним напрямую, включая локальный DNS. Исключение адреса транспорта AWG добавляется к этому списку.

Приоритет: служебные проверки и транспорт адаптера → локальная сеть (если включено) → правила сайтов → прямые исключения приложений → прямые GeoIP-исключения → VPN. GeoIP-исключение действует и для выбранного VPN-приложения. Пустой список во втором режиме направляет остальной трафик напрямую; явные правила сайтов сохраняют приоритет.

В «Маршрутизации» для сайтов доступны режимы «Все сайты», «Через VPN» и «Напрямую, в обход VPN». «Все сайты» не добавляет ограничений раздела. «Через VPN» направляет только список через VPN, остальные назначения — напрямую. Режим обхода направляет список напрямую. Списки VPN/обхода сохраняются раздельно и отображаются при выборе соответствующего режима. Укажите домены по одному на строку или через запятую; HTTP/HTTPS-ссылки преобразуются в домен, кириллица поддерживается. Правило охватывает домен и поддомены. Для YouTube обычно нужны `youtube.com` и `googlevideo.com`; сайт может обращаться и к другим CDN. Отдельные страницы одного домена не различаются. Правила применяются после переподключения.

В разделе «Правила GeoIP» аналогичные режимы: «Все страны», «Через VPN» и «Напрямую, в обход VPN». Укажите коды стран, например `ru, by, kz`. В режиме «Через VPN» страны списка используют VPN, остальные назначения идут напрямую; пустой список направляет остальной трафик напрямую. В режиме обхода страны списка идут напрямую. «Все страны» отключает ограничения GeoIP и загрузку его наборов. Правила сайтов и приложений имеют более высокий приоритет.

Для определения сайта используется сопоставление DNS-ответов и распознавание HTTP/TLS/QUIC на портах 80/443 с ограничением 300 мс. Если собственный DNS браузера и ECH скрывают имя, доменное правило может не распознаться. При пустых списках распознавание веб-трафика не добавляется.

GeoIP использует официальные SagerNet rule-set файлы, скачиваемые ядром с GitHub и кэшируемые на неделю. При первой загрузке нужна доступность GitHub. Это география IP, а не домена. В этой версии страны задаются как исключения прямого доступа.

Обычный DNS перехватывается TUN и отправляется параллельно по DoH к Cloudflare и Google через выбранный VPN. Используется первый корректный ответ; NXDOMAIN также считается корректным отрицательным ответом. Независимые транспорты уменьшают влияние сброса одного HTTP/2-соединения. Запрос к каждому резолверу ограничен 5 секундами. Если недоступен сам VPN-путь, оба резолвера также могут не ответить. Bootstrap DNS для адреса VPN-сервера использует системное разрешение до подключения/прямое подключение ядра. DNS выбранных для обхода приложений и сайтов также обрабатывается через VPN. Встроенный в приложения DoH следует маршруту самого приложения. В WireGuard/AWG .conf системные DNS/маршруты не применяются напрямую: маршрутизацией управляет sing-box, DNS-запросами адаптера — его userspace stack. IPv4 и IPv6 перехватываются; доступность IPv6 внутри туннеля зависит от профиля.

## Устойчивость и ресурсы

Нативный интерфейс без Electron/WebView. Опрос соединения раз в 30 секунд, обновление подписки раз в 6 часов, журнал ограничен по размеру. Запускаются только нужные ядра: sing-box; дополнительно Xray для XHTTP или адаптер AmneziaWG для AWG. Адаптер поддерживает TCP и UDP, работает только на loopback и требует случайный пароль. AWG допускает до 2048 одновременных SOCKS-подключений и до 128 UDP-назначений на ассоциацию. На Windows используется стандартный UDP-транспорт официального ядра: RIO воспроизводимо зависал в локальном тесте с 320 соединениями. Журнал интерфейса обновляется пакетами с ограниченной очередью.

Контроль проверяет HTTPS непосредственно через TUN. При ошибке основного адреса или ожидании дольше двух секунд запускается резервная проверка Google/Cloudflare; любой полученный HTTPS-ответ подтверждает доступность транспорта. Запросы ограничены 12 секундами, оставшиеся отменяются после первого успеха. Перезапуск выполняется после трёх циклов, в каждом из которых не ответил ни один адрес. Если процесс упал, ожидание трёх проверок не требуется. Между попытками увеличивается пауза; восстановление продолжается без ограничения числа попыток, с паузой до пяти минут. При отсутствии физической сети клиент ждёт её появления; смена интерфейса, IPv4-адреса или шлюза вызывает повторную привязку транспорта при следующем цикле контроля. Это не гарантия отсутствия обрывов: сервер, провайдер, сон Windows и смена сети могут разорвать TCP-сессии. После восстановления приложение может потребовать повторить запрос. Автоматический выбор другого сервера пока не реализован. Основной адрес проверки можно изменить.

**Kill switch включается в настройках (по умолчанию выключен).** Перед подключением устанавливаются постоянные фильтры Windows Filtering Platform для IPv4/IPv6. Во время обрыва, перезапуска ядер и после аварийного завершения клиента выход вне TUN заблокирован. Служебные соединения клиента и его ядер, loopback и DHCP разрешены; LAN разрешена только при включённом обходе LAN. Прямые правила сайтов и приложений работают через ядро при активном TUN. Ручное отключение VPN, штатный выход и выключение Kill switch с сохранением настроек снимают блокировку. После сбоя запустите клиент повторно и подключитесь либо выберите «Отключить» в трее. Без Kill switch при остановке ядра трафик может пойти напрямую. Команда «Выход» в меню трея завершает процессы; Windows Job Object также завершает дочерние ядра при аварийном закрытии клиента. Это ранняя версия: длительная работа, сон/пробуждение и TUN-маршрутизация на реальной пользовательской сети требуют отдельного испытания.

Ссылка и профили сохраняются в `%LOCALAPPDATA%/AsterVPN/settings.bin` с Windows DPAPI. Каталог доступен текущему пользователю, администраторам и SYSTEM. Рабочие конфигурации с ключами временно записываются в этот каталог, удаляются после отключения; после аварийного завершения файл может остаться до следующего запуска/подключения. Не делитесь этими файлами. Проверка TLS включена. Журнал не сохраняется на диск, секреты маскируются, сообщения дополнительных ядер скрываются.

VLESS/XHTTP отклоняет UDP/443 на VPN-маршруте: браузеры переходят с QUIC на HTTP/2. Прямые исключения сохраняются; AWG продолжает передавать QUIC нативно. Это соответствует [штатной политике Xray](https://xtls.github.io/en/config/outbound.html#_muxobject).

## Сборка и проверки

```powershell
./scripts/setup-core.ps1
./scripts/setup-xray.ps1
./scripts/build-awg.ps1   # Go 1.25+ либо vendor/go/bin/go.exe
dotnet run --project tests/AsterVPN.Tests.csproj -c Release
./scripts/build.ps1
```

Нужны Windows x64, .NET 8 SDK или новее и Go. Go-зависимости зафиксированы в `awg/go.mod` и `awg/go.sum`. Windows-клиент не имеет внешних NuGet-пакетов. Для self-contained сборки используйте `-SelfContained` и разрешённый источник NuGet для runtime packs. Обычная сборка использует установленный .NET Desktop Runtime 8.

`tests` проверяет импорт, приоритет правил и принимает конфигурации настоящим `sing-box check`. Go-тесты создают два локальных AWG-пира, передают зашифрованные TCP/UDP-данные через SOCKS и проверяют запрет анонимного подключения. `checks` — локальная диагностика приватной подписки; она читает DPAPI-файл, не включённый в поставку, и проверяет HTTPS без TUN. Результаты не содержат адресов серверов или ключей.

Официальные источники: https://sing-box.sagernet.org/ · https://github.com/XTLS/Xray-core · https://github.com/amnezia-vpn/amneziawg-go · https://github.com/INCY-DEV/incy-docs

### Изменения 0.4.12

Восстановление VLESS больше не зависит от доступности API подписки: при сетевой ошибке или ожидании более 8 секунд клиент повторно использует сохранённый профиль. Отмена пользователем и явное удаление/неоднозначность сервера в успешно полученной подписке сохраняют прежнее поведение. Одна попытка автоматического восстановления ограничена 90 секундами.

Резервный HTTPS-запрос запускается после двух секунд ожидания основного, не дожидаясь его полного тайм-аута. Успешный ответ отменяет остальные проверки. Сохранены три неудачных цикла перед перезапуском; параметры XHTTP и XMUX провайдера не меняются. 116 автоматических проверок пройдены, включая зависшие сайты, недоступную подписку и отмену.

### Изменения 0.4.11

Отменено принудительное `xmux.maxConcurrency=4` и добавление outbound XUDP-mux в XHTTP: клиент сохраняет XMUX провайдера либо использует штатные значения Xray. В контрольном тесте на одном packet-up-профиле четыре загрузки Google CDN без этих настроек дали 28,5 Мбит/с; повтор с настройками 0.4.10 завершился по тайм-ауту. Это ограниченный сетевой A/B-замер, не гарантия постоянной скорости.

Отменено обязательное получение нового VLESS-профиля при каждом подключении. Сохранённый профиль сначала используется как есть; обновление параметров выполняется после неудачной начальной проверки или при восстановлении. Обычное обновление подписки сохраняется. Режимы `packet-up`, `stream-up`, `stream-one`, `auto` передаются из профиля без переопределения; каждый проверяется настоящим Xray. Используемый режим должен поддерживаться конфигурацией сервера. AWG оставлен без изменений.

### Изменения 0.4.10

При включённом автообновлении перед подключением VLESS/XHTTP клиент получает актуальные параметры выбранного сервера из подписки. Это исправляет использование старых REALITY `serverName`/`shortId` и XHTTP Host после их ротации у провайдера. При восстановлении после сетевых сбоев параметры также запрашиваются заново вместо бесконечного повторения старой конфигурации. Если выбранный сервер удалён или неоднозначен, клиент требует обновить список и выбрать сервер; на другой сервер автоматически не переключается. Обновление можно отменить кнопкой подключения. AWG и локальные профили остаются без этого запроса. При выключенном автообновлении подписку нужно обновлять вручную.

Диагностика подтвердила отличия сохранённых и свежих REALITY-параметров; старый профиль одного сервера давал ошибку сертификата, свежий прошёл HTTPS. Это исправление актуальности профилей, а не гарантия отсутствия сетевых тайм-аутов: отдельные зависания под параллельной нагрузкой наблюдались и со свежими параметрами.

### Изменения 0.4.9

AWG: UDP-назначения обслуживаются отдельными очередями и обработчиками. Зависший DNS, dial или запись одного назначения больше не блокируют приём остальных назначений в SOCKS-ассоциации. Очереди ограничены 256 КиБ на назначение и 2 МиБ на ассоциацию; переполнение отбрасывает UDP-пакеты вместо неограниченного накопления задержки. Закрытие ассоциации отменяет ожидающие подключения и освобождает обработчики. Добавлен тест с зависшим назначением и переполнением его очереди.

TUN учитывает MTU AWG-профиля в диапазоне 1280–1400 вместо постоянного 1400: это уменьшает риск фрагментации QUIC при меньшем MTU AWG. Для профилей с MTU ниже 1280 сохраняется минимум IPv6 1280, поэтому фрагментация в таких профилях всё ещё возможна. VLESS/XHTTP по умолчанию использует до четырёх потоков на транспортное соединение; пул расширяется по нагрузке. Явные настройки XMUX провайдера сохраняются. Это уменьшает совместное ожидание приложений на одном HTTP/2-транспорте, но не гарантирует рост скорости на каждом сервере.

`python scripts/measure-current-vpn.py` измеряет один и четыре TCP-потока через уже работающий VPN, не запускает второй AWG-пир с теми же ключами и не меняет маршруты. Малые загрузки включают DNS/TLS и разгон TCP, поэтому это диагностический замер, а не предел пропускной способности. Изменения проверены локальными тестами; скорость YouTube после установки требует повторной проверки на реальном соединении.

### Изменения 0.4.8

Исправлена ошибка `TypeInfoResolver` при сохранении конфигурации перед запуском AWG: параметры сериализации наследуются от `JsonSerializerOptions.Default`. Добавлен регрессионный тест этого пути. Пинг AWG отображается через ICMP. При включённом обходе LAN частные сети исключаются из TUN. Устранение тайм-аутов внешних прямых соединений пока не подтверждено.

### Изменения 0.4.7

Xray обновлён до 26.10.21: исправлено размножение HTTP/2-соединений при зависшем TLS в XHTTP (регрессионный тест `python tests/xhttp_stalled_handshake.py`). Проверка HTTPS показывает время успешного запроса отдельно от тайм-аутов предыдущих адресов; резервный адрес отмечается в статусе. Это время HTTPS-запроса, а не ICMP-пинг. Версия в интерфейсе, User-Agent и заголовках подписки берётся из метаданных сборки, версия установщика — из того же проекта.

### Изменения 1.0.2

В настройках добавлены Kill switch, автозапуск при входе в Windows и автоподключение к последнему выбранному серверу. Новые параметры выключены по умолчанию. После выбора нажмите «Сохранить настройки». Автозапуск использует отдельное задание планировщика для текущего пользователя, InteractiveToken и HighestAvailable: пароль не сохраняется, запуск выполняется в трей с аргументом `--startup`. Автоподключение работает при любом запуске клиента. Обновление подписок и автозапуск самого клиента — разные настройки. Kill switch применяется при сохранении для активного VPN, либо при следующем подключении; параметры маршрутизации требуют переподключения.

При Kill switch bootstrap DNS ядра использует DoH; адреса серверов Xray/AWG также разрешаются через HTTPS без системного DNS. Возможны разрешённые DNS-запросы к LAN-резолверу при включённом обходе LAN. Блокировка не является защитой до первого подключения или после ручного отключения.

Проверка форматов, настроек и DNS-конфига: `dotnet run --project tests/AsterVPN.Tests.csproj -c Release`. Дополнительная проверка принятия WFP-правил Windows (из повышенного терминала): добавьте `-- --wfp-validate`. Она создаёт правила внутри транзакции и откатывает её без изменения действующей фильтрации.
